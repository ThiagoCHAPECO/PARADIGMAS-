**1\. A genealogia das linguagens não é uma escada de progresso.**  
**Explique essa afirmação e apresente dois fatores históricos que fazem**  
**uma linguagem influenciar outra sem necessariamente substituí-la.**  
**Objetivos: obj01, obj05 · Referência: Sebesta, cap. 2, páginas PDF 50, 51\.**

**R:** Dois fatores históricos que explicam uma linguagem influenciar outra sem substituí-la são:

Influência de conceitos e características: novas linguagens frequentemente aproveitam ideias já existentes em linguagens anteriores. Por exemplo, conceitos de estruturas de controle, tipos de dados e formas de organização dos programas foram sendo incorporados e aperfeiçoados em linguagens posteriores.

Necessidades e contextos diferentes: uma linguagem pode continuar sendo utilizada porque atende bem a determinado propósito, como aplicações científicas, sistemas comerciais ou programação de sistemas. Assim, mesmo com o surgimento de linguagens mais recentes, uma linguagem anterior pode permanecer relevante.

**2\. Plankalkül não foi implementada em sua época. Ainda assim, por que**  
**ela é relevante para a história das linguagens? Cite três recursos**  
**antecipados por seu projeto e explique o valor de um deles.**  
**Objetivos: obj01, obj02 · Referência: Sebesta, cap. 2, páginas PDF 52, 53\.**

**R:** A Plankalkül, desenvolvida por Konrad Zuse na década de 1940, é relevante para a história das linguagens de programação porque, apesar de não ter sido implementada na época em que foi projetada, apresentou conceitos que só seriam encontrados em linguagens posteriores. Por isso, ela é considerada uma linguagem pioneira, pois antecipou várias ideias importantes da programação.

Três recursos antecipados pela Plankalkül foram:

Tipos de dados estruturados, permitindo trabalhar com estruturas mais complexas do que valores simples.  
Vetores (arrays), possibilitando armazenar e manipular conjuntos de valores.  
Atribuição condicional, permitindo realizar atribuições dependendo de determinadas condições.

Um exemplo do valor desses recursos é o uso de vetores. Esse conceito é fundamental porque permite organizar vários valores relacionados em uma única estrutura, facilitando o armazenamento e o processamento de grandes conjuntos de dados. A presença desse recurso na Plankalkül mostra como Zuse antecipou conceitos que se tornariam comuns em linguagens de programação posteriores.

**4\. Explique por que o projeto Fortran precisou convencer**  
**programadores de que código traduzido podia competir com código de**  
**máquina escrito à mão. Relacione desempenho, custo de programação**  
**e adoção.**  
**Objetivos: obj01, obj02, obj04 · Referência: Sebesta, cap. 2, páginas PDF 56, 60\.**  
**R**: A equipe do Fortran precisou convencer os programadores de que o código gerado pelo compilador poderia ter desempenho próximo ao código de máquina escrito à mão. Isso era importante porque os programadores temiam perder velocidade ao usar uma linguagem de alto nível.

O Fortran também reduzia o custo e o tempo de programação, tornando o desenvolvimento mais rápido e simples. Assim, ao oferecer bom desempenho e maior produtividade, a linguagem conseguiu conquistar a adoção dos programadores.

**14\. Compare o papel dos objetos em Smalltalk, C++ e Java. Inclua na**  
**resposta o compromisso de C++ com C e a estratégia de portabilidade**  
**de Java.**  
**Objetivos: obj02, obj03 · Referência: Sebesta, cap. 2, páginas PDF 98, 103\.**  
**R:**Smalltalk é a linguagem mais puramente orientada a objetos das três. Sebesta destaca que Smalltalk foi a primeira linguagem a oferecer suporte completo à programação orientada a objetos. Nela, praticamente tudo é tratado como objeto, e a interação entre os objetos ocorre por meio do envio de mensagens. Dessa forma, o programa é estruturado essencialmente como uma coleção de objetos que colaboram entre si.  
C++, por outro lado, foi desenvolvido a partir de C, incorporando recursos de orientação a objetos inspirados em linguagens como Simula e Smalltalk. Portanto, C++ assumiu um compromisso com a compatibilidade e as características de C: não abandonou a programação procedural nem os recursos de baixo nível da linguagem original. Por isso, C++ permite tanto programação procedural quanto programação orientada a objetos.  
Já em Java, os projetistas partiram de C++, mas removeram ou modificaram vários recursos para tornar a linguagem menor, mais simples e mais confiável. Uma diferença importante apontada por Sebesta é que Java não permite subprogramas independentes: todos os métodos precisam estar definidos dentro de classes. Portanto, a programação em Java é essencialmente orientada a objetos.

**17\. C\# foi apresentada como evolução no ambiente .NET. Compare duas**  
**decisões de C\# com suas correspondentes em Java ou C++ e explique o**  
**problema que pretendem resolver.**  
**Objetivos: obj02, obj04 · Referência: Sebesta, cap. 2, páginas PDF 113, 116\.**  
**R:**decisão destacada por Sebesta é a criação das propriedades. Em Java, é comum manter um atributo privado e criar métodos get e set para controlar seu acesso. C\# permite representar esse acesso por meio de uma propriedade, na qual os métodos get e set são chamados implicitamente.  
Em Java:  
class Pessoa {  
    private String nome;  
    public String getNome() {  
        return nome;  
    }  
    public void setNome(String nome) {  
        this.nome \= nome;  
    }  
}

Em C\#:  
class Pessoa  
{  
    private string nome;  
    public string Nome  
    {  
        get { return nome; }  
        set { nome \= value; }  
    }  
}  
A vantagem é que o C\# permite acessar a propriedade de maneira semelhante a um atributo:  
Pessoa p \= new Pessoa();  
p.Nome \= "Carlos";  
Console.WriteLine(p.Nome);  
O problema que essa decisão procura resolver é a necessidade de escrever e chamar explicitamente vários métodos de acesso (get e set), mantendo ao mesmo tempo o encapsulamento dos dados. Sebesta apresenta as propriedades justamente como uma alternativa aos atributos públicos, permitindo controlar leitura e escrita sem exigir chamadas explícitas aos métodos.

**18\. Diferencie XSLT e JSP quanto a entrada, processamento e saída. Por**  
**que ambas podem ser chamadas de linguagens híbridas de marcação e**  
**programação?**  
**Objetivos: obj02, obj03 · Referência: Sebesta, cap. 2, páginas PDF 116, 118\.**  
**R:** Com base no capítulo 2 de Robert W. Sebesta. A principal diferença é que XSLT é voltada principalmente para transformar dados XML em outra representação, enquanto JSP é voltada para gerar documentos Web dinâmicos no servidor. As duas são híbridas porque, além da marcação, permitem inserir ou especificar ações de processamento e lógica de programação.  
XSLT: Entrada: recebe um documento XML de dados e um documento XSLT, que contém as regras de transformação.  
Processamento: o processador XSLT procura padrões (templates) no documento XML e aplica as instruções de transformação correspondentes. Também possui recursos de programação, como iteração (for-each) e ordenação.  
Saída: produz um novo documento, que pode ser XML, HTML ou texto simples.  
JSP: Entrada: recebe uma página JSP, normalmente composta por uma mistura de HTML e código Java, que é solicitada pelo navegador.  
Processamento: o processador JSP transforma a página em um servlet. O código Java é incorporado ao servlet, enquanto o HTML é convertido em instruções de impressão. Elementos da JSTL também podem controlar o processamento, por exemplo, utilizando condições.  
Saída: o servlet é executado no servidor e gera um documento HTML, que é enviado de volta ao navegador.
